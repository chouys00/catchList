# 🎮 Steam 每月優質遊戲發掘工具

自動抓取並發掘 Steam 上適合「單人遊玩」或「親友同樂」的優質新遊戲，排除 MMO 與多人競技，整理成 `遊戲.md` 報告。

---

## 📂 目錄結構

```
steam_discovery/
├── main.js          ← 主程式（執行這個）
├── config.js        ← 設定（過濾開關、評論數門檻）
├── fetcher.js       ← Steam Search 爬蟲與 API 串接
├── writer.js        ← 輸出 遊戲.md
├── package.json     ← npm 依賴
└── 遊戲.md          ← 自動生成的報告（執行後出現）
```

---

## ⚡ 快速開始

### 1. 安裝依賴
請在專案目錄下執行：
```bash
npm install
```

### 2. 執行
本工具採用**歷史增量與檔案鎖定邏輯**。執行後會自動偵測 `遊戲.md` 中已經寫入的月份，並自動補齊「6個月前（沉澱期）」至今所有遗漏的月份。
```bash
node main.js
```

要在本機建立少量預覽資料，可指定單月、輸出檔與取樣數量：

```bash
node main.js --year 2026 --month 3 --sample-limit 3 --output preview/遊戲.md
```

預覽報告與一鍵開啟頁都會寫在 `preview/` 內，不會修改正式雲端報告。官方類型與社群標籤都直接保存在 `遊戲.md`，不再建立 `遊戲標籤.json`。

若要重試既有報告中缺漏的社群標籤，可執行：

```bash
node main.js --backfill-tags --output preview/遊戲.md
```

### Steam 搜尋限流規則

- 商店搜尋頁每次請求至少間隔 10 秒。
- 收到 HTTP 429 時，優先遵守 Steam 回傳的 `Retry-After`；未提供時至少等待 60 秒，最多重試 2 次。
- 搜尋定位或掃描失敗時，整個月份以失敗結束，不得寫入空月份，也不得繼續下一個月份。
- 社群標籤可個別失敗，不影響該遊戲寫入月報；失敗項目會明確寫成「尚未補齊社群標籤」，供閱讀器顯示及下次補抓。

## 🔍 過濾與篩選機制

1. **沉澱期（6 個月）**：
   - 剛上市的遊戲評價起伏大、數量少。本工具預設只撈取上市已滿 6 個月的遊戲（例如 7 月執行時，只評估 1 月上市的遊戲），給予足夠的時間讓口碑發酵。
2. **評價門檻**：
   - 納入好評率至少 85%、總評論數大於 500 則的遊戲。
   - 以 Steam 搜尋頁顯示的好評率與總評論數判定，不再限制特定評價標籤。
3. **單人與合作同樂優化**：
   - 排除 MMORPG (大型多人線上) 以及 MOBA、大逃殺等純多人對戰競技遊戲（如 CS2、Apex）。
   - 保留支援單人遊玩 (Single-player) 或合作遊玩 (Co-op) 的遊戲。
4. **排除搶先體驗 (Early Access)**：
   - 排除掛有 Early Access (ID 70) 標籤的未完成遊戲。
5. **排除實用工具軟體**：
   - 排除 Wallpaper Engine 等非遊戲軟體。
6. **語言、成人內容與免費遊戲**：
   - 搜尋全語系遊戲。繁體中文或簡體中文任一成立，就統一標示為「支援中文」，不分開記錄語系。
   - 保留 18+ 成人遊戲，並以 `[18+]` 標記。
   - 排除免費遊戲。
