# CatchList Reader

CatchList 的 Windows 桌面閱讀器，直接讀取資料夾內的 `動畫.md`、`電影.md`、`遊戲.md` 與 `真人劇年度.md`。

目前正式建置入口為 Electron 的 `npm run reader:build`。請用畫面左上角與視窗標題的版本確認正在執行的程式，不要只看 EXE 檔名；舊的 Tauri 安裝版不會隨可攜版重建而更新。

`npm run reader:build` 會先執行版本與回歸防護。版本低於根目錄的 `reader-release-policy.json`、`package-lock.json` 未同步，或真人劇、隱藏、社群標籤及遊戲篩選測試失敗時，都會停止打包。每次發行新版時，閱讀器版本與發行基準必須一起遞增。

1.0.9 通過 46 項回歸測試，封裝的 19 個來源檔與工作區逐位元組一致。`test-support/release-audit.cjs` 以正式報告的隔離副本驗證封裝介面：標籤點擊、隱藏復原、評論數選單、封面尺寸與真人劇地區及名稱搜尋皆通過。此測試使用目前資料層，未修改正式報告，亦未開啟外部連結。使用者先前實際啟動哪份 EXE 仍未確認。

## 1.0.18 動畫歷史格式相容

- 動畫舊資料只有名稱與評分時仍會顯示；缺少集數與類型時以「集數與類型未提供」標示。
- 無評分劇場版保留在清單中，以「—」顯示分數；劇場版改為獨立區段與篩選條件，不再沿用前一季年份。
- 解析報告時檢查無法辨識的區段與作品行，畫面會列出行號警告，避免資料無聲漏讀。
- 劇場版重新分類後仍辨識舊版收藏、隱藏及新收錄紀錄。

## 1.0.17 效能改善

- 切換類別、收藏與隱藏操作可重用報告解析結果。檔案大小、修改／變更時間或檔案識別資料改變時重新解析；真正寫入或刪除仍即時讀檔驗證。
- 搜尋名稱及標籤預先整理，篩選條件未變時，捲動續載直接重用排序結果。新收錄、收藏與手動來源仍參與篩選。
- 每批最多四個封面網址合併存檔一次；存檔失敗保留記憶體內容，下一批可再試。意外終止最多重新查詢尚未完成的一批封面，不影響報告與個人紀錄。

## 1.0.16 工具列留白與側欄關閉

- 移除各頁的「重新讀取」入口；切換類別或重新開啟閱讀器時仍會讀取最新資料。
- 遊戲頁直接顯示「新增遊戲」按鈕，移除只剩單項操作的選單。收錄資訊、更新詳情及新增按鈕分組排列，與下方分隔線保留 14px 留白。
- 新增遊戲側欄可點外側遮罩、按 Escape 或關閉按鈕取消；欄內點擊或從欄內拖曳到外側不會誤關。儲存期間暫停關閉，避免無法確認是否已寫入。

## 1.0.15 遊戲手動收錄

- 只有遊戲頁提供「遊戲操作 → 新增遊戲」，輸入 Steam AppID 或商店網址，預覽後按「加入清單」。重新讀取也移到此選單，遊戲頁移除「開啟目前結果」；其他類別維持原有功能。
- 新增表單使用右側面板，窄視窗改為全寬。遊戲名稱下方標示「手動加入」，可在展開的篩選區選「只看手動加入」，與搜尋、排序及收藏一起使用。
- 可收錄未達評價門檻、免費、搶先體驗、多人及未發售遊戲；不支援 DLC、試玩版或非遊戲軟體。本版不提供自訂標籤、批次新增或資料更新。
- 手動資料保存在報告旁的 `.catchlist-manual-games.json`，不寫入 `遊戲.md`，不影響每月完成月份。複製或同步清單時須包含此檔；舊閱讀器不會顯示手動遊戲。
- 同款以 Steam AppID 合併；之後出現在自動報告時，顯示報告資料並保留手動來源、收藏與隱藏狀態。已收錄遊戲不重複加入，隱藏中的遊戲可從新增面板恢復。
- 尚無評論與讀取失敗分開顯示；不確定日期不猜測年月。排序時缺值置後，設定最低評價、評論數或年月條件會排除資料不足的遊戲。
- 評論使用全語系、Steam 購買來源的摘要，排除 Steam 預設判定的離題評論。只有名稱與遊戲類型可確認時才允許加入；評論與標籤個別失敗會保留缺漏提示。
- 刪除手動遊戲會移除手動紀錄；同時存在報告時，確認畫面會明示兩個來源都將刪除。雙來源刪除使用短期 `.catchlist-game-transaction.json` 保護中斷復原，成功後即移除，不提供成功刪除後復原。
- 手動檔案損壞時保留原檔並停止新增／刪除，仍能閱讀正常的 Markdown。偵測到預覽期間檔案變更時須重新讀取，跨電腦同步衝突仍不自動合併。

## 1.0.14 排序、新收錄與緊湊工具列

- 搜尋、排序、新收錄和篩選入口集中同一列；年份、評分、中文支援與標籤預設收起。篩選入口顯示已套用條件數，收起不清除條件。
- 更新詳情改為浮層，可再次點擊、點外側或按 Escape 關閉。結果數直接顯示於工具列，移除重複的大標題。
- 遊戲可依發售日、好評率或評論數排序；動畫可依分數或年份，電影與真人劇另有票數排序。排序可與收藏、搜尋和新收錄組合使用。
- 新收錄依各類別上次來訪時的作品識別資料比較，首次使用只建立基準。本次來訪中新加入的作品持續標記，重新讀取或收藏不清除；下次啟動程式時以上次已收錄作品為基準。未開啟的類別不會提前標成已來訪。
- 來訪紀錄另存資料夾中的 `.catchlist-visits.json`，可隨 Google Drive 同步；不改寫 Markdown。評分變更或恢復隱藏不算新收錄。非遊戲作品改名或移到別的收錄區段仍可能被視為新作品。
- 新收錄從閱讀器首次辨識該作品起判定，不能還原安裝本版前的收錄時間。紀錄損壞或無法儲存時顯示警告，仍可閱讀清單；同時從多台裝置開啟沒有衝突合併保證。

## 1.0.13 返回頂部

清單向下捲動超過 480 像素後，右下角會顯示返回頂部按鈕。按鈕支援滑鼠、觸控與鍵盤操作；提示訊息會自動移到按鈕上方，避免遮擋。

## 1.0.12 遊戲欄位順序

遊戲清單將好評率移到發售日之前，桌面順序為「封面、遊戲名稱、好評率、發售日、中文、社群標籤、管理」。手機版維持好評率與日期同組呈現，並優先顯示好評率。

## 1.0.11 個人清單與更新摘要

- 每筆作品旁的書籤可加入或取消收藏；遊戲的「待玩收藏」及其他類別的「待看收藏」沿用原本搜尋、篩選功能。
- 收藏另存資料夾內的 `.catchlist-favorites.json`，不改寫報告。新增月份與更新分數後保留；作品改名可能需要重新收藏。隱藏中的收藏暫不顯示，恢復後仍保留。
- 「隱藏管理」依目前類別列出過往隱藏紀錄，支援名稱搜尋與逐筆恢復。重開程式後仍可使用；原始作品已被刪除時只清除失效隱藏紀錄，不重建作品。
- 收錄範圍摘要可展開查看四類資料。`npm run update:all` 從本版起把每次執行結果、上次成功時間與本次新增數記在報告旁的 `.catchlist-update-status.json`。沒有舊紀錄時顯示「尚無每月執行紀錄」，不從檔案修改時間推斷成功。
- 單獨執行 `update:anime`、`update:movies`、`update:games` 及年度真人劇不產生整批執行紀錄，請以各自輸出為準。未完成的紀錄只表示沒有記錄完成，不能確認程式仍在執行。
- 「重新讀取」會讀取最新報告與個人紀錄。更新摘要不會宣稱 Google Drive 已完成上傳，實際上傳狀態請查看 Google Drive 同步程式。

個人 JSON 與 Markdown 放在同一個 Google Drive 資料夾時可一併同步。請避免在多台電腦尚未同步完成時同時編輯，這個版本沒有跨裝置合併衝突功能。

## 開發指令

```powershell
npm run reader:dev
```

開發時若報告不在閱讀器旁，可設定資料夾：

```powershell
$env:CATCHLIST_DATA_DIR = 'G:\我的雲端硬碟\CatchList'
npm run reader:dev
```

## 測試與建置

```powershell
npm run reader:test
npm run reader:build
```

可攜版會輸出到 `catchlist_reader/dist/`。正式使用時，把 EXE 放到四份 Markdown 的同一資料夾。

隱藏作品時會把紀錄寫入資料資料夾的 `.catchlist-hidden.json`，不會修改 Markdown 報告；閱讀器內可立即復原最後一次隱藏。
