# CatchList Reader

CatchList 的 Windows 桌面閱讀器，直接讀取資料夾內的 `動畫.md`、`電影.md`、`遊戲.md` 與 `真人劇年度.md`。

目前正式建置入口為 Electron 的 `npm run reader:build`。請用畫面左上角與視窗標題的版本確認正在執行的程式，不要只看 EXE 檔名；舊的 Tauri 安裝版不會隨可攜版重建而更新。

`npm run reader:build` 會先執行版本與回歸防護。版本低於根目錄的 `reader-release-policy.json`、`package-lock.json` 未同步，或真人劇、隱藏、社群標籤及遊戲篩選測試失敗時，都會停止打包。每次發行新版時，閱讀器版本與發行基準必須一起遞增。

## 1.0.55 遊戲截圖快篩

- 在遊戲「全部」頁點「截圖快篩」，依目前的搜尋、篩選與排序逐款呈現最多三張 Steam 實際遊戲截圖，可點擊放大。
- 按 `1` 標記沒興趣、`2` 加入待玩收藏、`3` 或右方向鍵略過；`Esc` 返回清單。固定操作列在窄視窗也可直接使用。
- 隱藏沿用「暫不考慮」紀錄，不修改 Markdown。可立即復原上一款的隱藏、收藏或略過，之後也能從隱藏管理恢復。
- 已看作品與目前位置依資料夾保存在本機，關閉或重新啟動後可續接。略過的作品仍留在全部清單；看完後可重新瀏覽目前仍在清單中的作品。
- 只在查看作品時查詢截圖，成功的截圖網址保存 30 天；沒有截圖的結果保存一小時，網路失敗可重試。圖片內容使用瀏覽器快取。

## 1.0.52 遊戲多選與批次處理

- 按「多選」後勾選遊戲，可將整批移至待觀察、候補、玩過了或暫不考慮，也可批次刪除。隱藏管理維持單筆操作。
- 「全選已載入」只勾選當下已載入的結果；捲動載入更多遊戲不會自動勾選。排序與標籤展開保留勾選，搜尋、篩選、分類、重新讀取與更換資料夾會清空勾選。
- 批次隱藏保留收藏及原隱藏時間，已在同一分類的項目略過。本次開啟期間可立即復原最近一批隱藏；相關紀錄若已被修改，就停止整批復原。
- 批次刪除會先顯示完整遊戲名單與來源。確認後，先將受影響來源檔備份至目前資料夾的 `.catchlist-backups/batch-delete/`，核對內容及 SHA-256，再刪除相同 Steam AppID 的全部收錄。雙來源寫入失敗時整批復原。
- 備份資料夾含來源原檔與 `manifest.json`，供人工還原，不會自動清理。還原前請先保留目前來源檔，並核對備份後新增的資料；直接覆蓋整份來源會連帶移除後續新增內容。
- 上方維持搜尋、排序與篩選入口，詳細條件集中在展開面板；批次操作列只在多選模式顯示，捲動時固定在頁首下方。

## 1.0.51 好評率快速輸入

- 好評率依左上限、右下限排列，空白表示不限；可選 85、90、95、97%，或手動輸入小數。聚焦輸入框後可用滾輪微調，Shift 改為每次 0.1%。
- 遊戲年份、月份篩選移除，列表發售日保留。發售日與好評率表頭可切換雙向排序，與排序選單共用狀態。

## 1.0.45 更新詳情以收錄狀態與實際新增為主

- 主表顯示目前收錄狀態、最後一次新增的時間與筆數；檢查結果、檔案修改時間與錯誤移至可展開的檢查紀錄，真人劇另列年度清單。
- 從報告既有起點核對到應收錄期間，缺段會提示數量與期間；不以最新標題存在就宣稱補齊，也不代表每部作品及評分已重新核對。
- 桌面以表格呈現，手機保留項目與狀態，時間與筆數附上欄位名稱；沒有新增紀錄時不推測時間或顯示零筆成功。

## 1.0.44 保留實際更新成功紀錄

- 新增 0 筆顯示「檢查完成，無新增」，不覆蓋最後一次有新增資料的成功時間與筆數。執行失敗及執行中也保留該紀錄。
- 更新詳情分別列出最近執行時間、最後更新成功時間及當次新增數；舊紀錄沒有可信時間時不依檔案修改時間推測。

## 1.0.43 動畫資料改接 Tenrai

- 動畫作品搜尋、封面及預告改接 Tenrai，移除已停用的公開來源呼叫，保留仍有效的 AniList 媒體備援。

## 1.0.42 修正遊戲時數連結

- 修正所有遊戲時數按鈕都顯示「外部連結不正確或數量過多」的問題，允許 HowLongToBeat 的 HTTPS 名稱搜尋入口。
- 補上按鈕網址經正式外連驗證後交給瀏覽器的回歸測試，並確認既有 Steam、Google、IMDb 與 YouTube 入口仍可開啟。

## 1.0.41 遊戲時數查詢

- 遊戲名稱旁的複製按鈕右側新增時鐘圖示，點擊後以外部瀏覽器開啟 HowLongToBeat 搜尋結果。優先使用原文名稱，缺少原名時改用顯示名稱；滑鼠提示為「查詢遊戲時數（HowLongToBeat）」。
- 使用 `https://howlongtobeat.com/?q=名稱` 搜尋入口，由使用者選擇正確遊戲版本；不自動猜測網站遊戲編號，也不抓取或保存時數。

## 1.0.40 動畫來源對照

- 優先讀取報告旁的 `.catchlist-anime-sources.json`，直接依已保存的作品編號與網址顯示封面及宣傳影片，不重新用中文搜尋。舊版的「未配對」快取不會擋住新來源；使用者明確手動選定的作品仍優先。
- 來源檔可與 Google Drive 同步，圖片仍使用原本的瀏覽器快取。重新讀取會更新來源結果。來源檔損壞時保留原檔並顯示警告。
- 2025 春季至 2026 春季的 67 列已有 64 列補齊封面，59 列有來源提供的影片；3 列年份或版本衝突保留待確認。重複列維持原樣，64 列對應 62 組作品／季度。
- 之後每月抓取與「找動畫→寫入」會保留作品編號、原名、圖片及影片網址；舊暫存若缺少編號會停止寫入，須重新抓取。舊 Markdown 仍可閱讀，沒有來源對照的作品沿用原查詢方式。

## 1.0.39 動畫封面與宣傳影片

- 動畫清單新增直式封面、可放大預覽、宣傳影片標題與頻道。點擊影片才以外部瀏覽器開啟 YouTube，不自動播放。
- 接近可見範圍的作品才依序查詢；以 Bangumi 補原名，使用 Tenrai／MyAnimeList 資料，來源失敗時改用 AniList。名稱、年份與類型可確認且結果唯一時才自動套用；不確定時提供「選擇作品」，也可隨時「校正作品」。
- 媒體資料與封面網址長期存於 `%APPDATA%\catchlist-reader\anime-media-cache.json`。與遊戲頁相同，圖片內容使用 Electron 瀏覽器快取，仍可能因快取到期或清除而重新連線下載，不是永久保存圖片檔。
- 找不到對應作品的結果保存 24 小時；來源故障可重新查詢。封面、影片與補充集數／類型不改寫 Markdown、收藏或隱藏紀錄，原報告已提供的集數與類型優先顯示。
- 影片依來源提供，可能包含 PV 或其他宣傳影片；來源未提供時會顯示狀態，不以搜尋結果猜測影片。

## 1.0.38 遊戲封面請求紀錄

- 閱讀器執行時會將遊戲封面請求附加寫入 `%APPDATA%\catchlist-reader\steam-cover-requests.log`，每次關閉時記錄本次合計。檔案可在閱讀器仍開啟時查看。
- 紀錄分開計算向 Steam 查詢封面網址的作品資料請求、實際經過網路的封面圖片請求、從瀏覽器快取讀取圖片的次數與圖片載入失敗次數。HTTP 304 屬於網路請求，但不用重新下載完整圖片。
- 紀錄的是請求次數，不是實際傳輸位元組數；不保存完整網址、圖片或個人資料。讀取報告及原有封面快取方式不變。

## 1.0.36 動畫、電影與真人劇名稱操作

- 作品名稱可點擊，使用 Google 搜尋畫面上的名稱；名稱後方顯示外連圖示。
- 名稱旁的複製圖示只複製該作品名稱，與搜尋按鈕分開操作。真人劇既有的 IMDb 入口保留。

## 1.0.32 搜尋全部收錄

- 遊戲搜尋框旁新增「搜尋全部收錄」開關，可用名稱、原文名稱或 Steam AppID 跨分類查詢，包含收藏、待觀察、候補、玩過了與暫不考慮。
- 開啟時暫停其他篩選，結果標示目前分類，可直接收藏、重新分類或恢復顯示。分類後仍留在搜尋結果中。
- 關閉時恢復原本分頁、搜尋文字與篩選；點選分頁或切換媒體會退出。平常的「全部」仍排除已收藏或隱藏遊戲。
- 空白搜尋不列出全部遊戲；已失效的隱藏紀錄不算目前收錄。

## 1.0.31 收藏與探索清單分流

- 已收藏作品不再出現在「全部」清單及其搜尋結果，只會顯示在待玩或待看收藏頁。
- 收藏後作品會立即離開「全部」清單；取消收藏後則回到「全部」清單。
- 頁籤數量、新收錄數量與篩選選項會依目前檢視計算，避免把收藏作品重複算入第一頁。

## 1.0.30 遊戲名稱快速複製

- 遊戲名稱旁新增複製圖示，一次複製中文顯示名稱與英文原名，每個名稱各占一行。
- 中英文名稱相同或其中一項空白時，只複製一份。複製圖示與 Steam 跳轉分開，按下後會顯示完成提示。
- 複製按鈕支援鍵盤操作與螢幕閱讀器；窄版畫面使用較大的觸控範圍。

## 1.0.21 遊玩模式圖示與篩選整理

- 遊戲列在「中文」旁增加窄版「模式」欄：萊姆綠單人剪影表示官方列單人、未列多人功能；米白群像表示含任一多人功能（也可能支援單人）；問號表示未確認。以輪廓辨識，不依賴欄位標題或顏色。滑鼠停留或螢幕閱讀器可讀完整說明。
- 「篩選」展開後先顯示全部／單人／多人／未確認，再列有明確欄名的年月、好評率、評論數、中文與來源。桌面六欄、中型三欄、手機兩欄；收起保留條件，清除篩選同步重設模式。
- 只使用指定的 Steam 官方功能 ID 分類。多人包含一般多人、合作、MMO、共享／分割畫面、跨平台多人及區域網路合作；PvP 類型不列入。遠端同樂可用於單人遊戲的觀看與輪流操作，與親友同享、排行榜及一般遠端串流一樣，不單獨作為多人依據。
- 舊報告的官方功能另外存於報告旁 `.catchlist-game-features.json`，複製或同步清單時請包含此檔；缺檔顯示未確認。此次由 2026-09-10 留存的商店快照補齊 3,111 款，並在載入時依現行規則分類，不代表今日重新查詢結果。
- 每月新增遊戲將官方功能 ID 保存在標題的 `商店功能:` 欄位，手動加入則存在手動清單；新資料優先於舊快照。原有歷史 Markdown、收藏及隱藏識別不變。
- 正式功能適用 Electron 可攜版；舊 Tauri 介面未更新。

## 1.0.18 動畫歷史格式相容

- 動畫舊資料只有名稱與評分時仍會顯示；缺少集數與類型時以「集數與類型未提供」標示。
- 無評分劇場版保留在清單中，以「—」顯示分數；劇場版改為獨立區段與篩選條件，不再沿用前一季年份。
- 解析報告時檢查無法辨識的區段與作品行，畫面會列出行號警告，避免資料無聲漏讀。
- 劇場版重新分類後仍辨識舊版收藏、隱藏及新收錄紀錄。

## 1.0.17 效能改善

- 切換類別、收藏與隱藏操作可重用報告解析結果。檔案大小、修改／變更時間或檔案識別資料改變時重新解析；真正寫入或刪除仍即時讀檔驗證。
- 搜尋名稱及標籤預先整理，篩選條件未變時，捲動續載直接重用排序結果。新收錄、收藏與手動來源仍參與篩選。
- 每批最多四個封面網址合併存檔一次；存檔失敗保留記憶體內容，下一批可再試。意外終止最多重新查詢尚未完成的一批封面，不影響報告與個人紀錄。

## 1.0.16 工具列留白與側欄關閉

- 移除各頁的「重新讀取」入口；切換類別或重新開啟閱讀器時仍會讀取最新資料。
- 遊戲頁直接顯示「新增遊戲」按鈕，移除只剩單項操作的選單。收錄資訊、更新詳情及新增按鈕分組排列，與下方分隔線保留 14px 留白。
- 新增遊戲側欄可點外側遮罩、按 Escape 或關閉按鈕取消；欄內點擊或從欄內拖曳到外側不會誤關。儲存期間暫停關閉，避免無法確認是否已寫入。

## 1.0.15 遊戲手動收錄

- 只有遊戲頁提供「新增遊戲」，輸入 Steam AppID 或商店網址，預覽後選「待觀察」、「候補」或「收藏」，再按加入按鈕。預設候補；從待觀察頁開啟時預設待觀察；加入後可直接查看對應清單。遊戲頁移除「開啟目前結果」；其他類別維持原有功能。
- 新增遊戲與分類使用同一筆交易儲存，寫入失敗或中斷時可復原，避免遊戲加入後漏掉分類。既有手動遊戲不會自動重新分類。
- 新增表單使用右側面板，窄視窗改為全寬。遊戲名稱下方標示「手動加入」，可在展開的篩選區選「只看手動加入」，與搜尋、排序及收藏一起使用。
- 可收錄未達評價門檻、免費、搶先體驗、多人及未發售遊戲；不支援 DLC、試玩版或非遊戲軟體。本版不提供自訂標籤、批次新增或資料更新。
- 手動資料保存在報告旁的 `.catchlist-manual-games.json`，不寫入 `遊戲.md`，不影響每月完成月份。複製或同步清單時須包含此檔；舊閱讀器不會顯示手動遊戲。
- 同款以 Steam AppID 合併；之後出現在自動報告時，顯示報告資料並保留手動來源、收藏與隱藏狀態。已收錄遊戲不重複加入，隱藏中的遊戲可從新增面板恢復。
- 尚無評論與讀取失敗分開顯示；不確定日期不猜測年月。排序時缺值置後，設定最低評價、評論數或年月條件會排除資料不足的遊戲。
- 評論使用全語系、Steam 購買來源的摘要，排除 Steam 預設判定的離題評論。只有名稱與遊戲類型可確認時才允許加入；評論與標籤個別失敗會保留缺漏提示。
- 刪除手動遊戲會移除手動紀錄；同時存在報告時，確認畫面會明示兩個來源都將刪除。雙來源刪除使用短期 `.catchlist-game-transaction.json` 保護中斷復原，成功後即移除，不提供成功刪除後復原。
- 手動檔案損壞時保留原檔並停止新增／刪除，仍能閱讀正常的 Markdown。偵測到預覽期間檔案變更時須重新讀取，跨電腦同步衝突仍不自動合併。

## 1.0.14 排序、新收錄與緊湊工具列

- 搜尋、排序、新收錄和篩選入口集中同一列；年份、評分、中文支援與標籤預設收起。篩選入口顯示已套用條件數，收起不清除條件。
- 更新詳情改為浮層，可再次點擊、點外側或按 Escape 關閉。結果數直接顯示於工具列，移除重複的大標題。
- 遊戲可依發售日、好評率或評論數排序；動畫可依分數或年份，電影與真人劇另有票數排序。排序可與收藏、搜尋和新收錄組合使用。
- 新收錄依各類別上次來訪時的作品識別資料比較，首次使用只建立基準。本次來訪中新加入的作品持續標記，重新讀取或收藏不清除；下次啟動程式時以上次已收錄作品為基準。未開啟的類別不會提前標成已來訪。
- 來訪紀錄另存資料夾中的 `.catchlist-visits.json`，可隨 Google Drive 同步；不改寫 Markdown。評分變更或恢復隱藏不算新收錄。非遊戲作品改名或移到別的收錄區段仍可能被視為新作品。
- 新收錄從閱讀器首次辨識該作品起判定，不能還原安裝本版前的收錄時間。紀錄損壞或無法儲存時顯示警告，仍可閱讀清單；同時從多台裝置開啟沒有衝突合併保證。

## 1.0.11 個人清單與更新摘要

- 每筆作品旁的書籤可加入或取消收藏；遊戲的「待玩收藏」及其他類別的「待看收藏」沿用原本搜尋、篩選功能。
- 收藏另存資料夾內的 `.catchlist-favorites.json`，不改寫報告。新增月份與更新分數後保留；作品改名可能需要重新收藏。隱藏中的收藏暫不顯示，恢復後仍保留。
- 「隱藏管理」依目前類別列出過往隱藏紀錄，支援名稱搜尋與逐筆恢復，並顯示評分與評分數；格式沿用原清單，例如電影的「36k票」、遊戲的「97%」「(1,768)」及真人劇的 IMDb 分數；失效紀錄顯示「—」。重開程式後仍可使用；原始作品已被刪除時只清除失效隱藏紀錄，不重建作品。
- 收錄範圍摘要可展開查看四類資料。`npm run update:all` 從本版起把每次執行結果、上次成功時間與本次新增數記在報告旁的 `.catchlist-update-status.json`。沒有舊紀錄時顯示「尚無每月執行紀錄」，不從檔案修改時間推斷成功。
- 單獨執行 `update:anime`、`update:movies`、`update:games` 及年度真人劇不產生整批執行紀錄，請以各自輸出為準。未完成的紀錄只表示沒有記錄完成，不能確認程式仍在執行。
- 「重新讀取」會讀取最新報告與個人紀錄。更新摘要不會宣稱 Google Drive 已完成上傳，實際上傳狀態請查看 Google Drive 同步程式。

個人 JSON 與 Markdown 放在同一個 Google Drive 資料夾時可一併同步。請避免在多台電腦尚未同步完成時同時編輯，這個版本沒有跨裝置合併衝突功能。

## 遊戲分類與好評率區間

遊戲列維持收藏、隱藏、刪除三個入口。隱藏按鈕可選「暫不考慮」「候補」「待觀察」「玩過了」，選取後可立即復原；方向鍵可移動選項，Escape 關閉並回到原按鈕。隱藏管理可搜尋、依原因篩選、修改原因或恢復顯示。

「候補」位於遊戲清單導覽，沿用完整遊戲列、搜尋、排序與篩選。候補列的收藏按鈕會加入收藏並解除隱藏；隱藏選單可恢復顯示。其他隱藏情況均保留原有收藏。失效紀錄只能清除，不重建作品。

好評率下限包含指定百分比，上限不包含指定百分比。例如最低 90%、未滿 95% 會顯示 90% 至低於 95% 的遊戲。上限預設不限；設定任一界限時排除無評分遊戲。上限小於或等於下限時顯示提示，暫不套用整組好評率條件，其他篩選照常運作。

分類保存在 `.catchlist-hidden.json`，遊戲原因為 `not_interested`、`backlog`、`watchlist`、`played`。缺少原因的舊遊戲紀錄讀取時視為「玩過了」，啟動不批次改寫。原因修改保留原識別碼與隱藏時間；不改報告欄位或每月完成判斷。

本次 1.0.22 驗收資料使用 `output/classification-acceptance-1.0.22/data`，保留正式報告、收藏、隱藏及手動收錄的副本。驗收操作只影響副本；本次不複製執行檔到雲端，也不清理雲端舊版。


1.0.23：清單導覽新增「玩過了」「暫不考慮」完整遊戲清單，與候補共用封面、名稱、評價、發售日、中文支援、遊玩模式、標籤及搜尋排序篩選。窄視窗導覽可換行。這兩個分類內切換收藏會保留原分類；可由原隱藏選單恢復顯示或修改原因。失效紀錄仍在隱藏管理清除。

1.0.24：遊戲的一般搜尋欄位可用中文名稱、英文名稱或 Steam AppID 查找清單內作品。

## 1.0.56 待觀察遊戲

「待觀察」屬於隱藏分類，遊戲頁有獨立頁籤；一般清單與待玩收藏不顯示。可用 Steam ID 或商店網址新增尚未上市、上市未滿六個月，或仍想觀察評價的遊戲，也可從既有遊戲的隱藏選單或多選操作移入。既有候補不會自動改分類。

待觀察沿用封面、搜尋、排序與篩選。點名稱可到 Steam 查看最新評價，按書籤會解除隱藏並移至待玩收藏；隱藏管理也可修改分類或恢復顯示。手動資料保留加入時的評價，不自動重抓；之後月報收錄時改用報告資料，仍保留待觀察分類。

版本採 1.0.56，避免覆蓋雲端資料夾已存在的 1.0.55。
