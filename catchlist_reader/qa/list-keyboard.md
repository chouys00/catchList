# 1.0.69 列表鍵盤捲動驗收

遊戲、動畫、電影與真人劇共用頁面捲動處理。↑／↓ 每次捲動 80 像素，長按持續捲動，Home 到頁首，End 到目前結果底部；不改變焦點、選取或個人紀錄。

## 大量列表

遊戲 End 使用既有每批 50 筆追加，每個畫面更新週期處理一批，完成後才立即定位到底部。重複 End 不增加並行工作；滑鼠、觸控、輸入、切換條件、重新繪製、視窗失焦及反向捲動都會取消未完成定位。

End 新增列透過 IntersectionObserver 在封面進入可視範圍後才查詢；沒有該 API 時，使用可視範圍檢查及捲動事件備援。一般捲動續載沿用既有行為。

## 元件相容

輸入框、備註、下拉選單、可編輯區與內部捲動區保留原有按鍵。彈出視窗及選單阻止背景捲動；視窗內非輸入元件上的按鍵只捲動內部可捲動區域。

實測發現 Chromium 原生 dialog 在按鈕取得焦點時，End 會捲動背景。因此除了檢查輸入框，也另外驗證備註視窗取消按鈕上的 End；修正後背景位置維持不變。分類選單已處理的 Home／End 不會被頁面處理器重複執行。

## 實際結果

- `test/list-keyboard-workflows.test.js` 使用正式 renderer、preload 與隔離 Chromium 視窗，透過真實鍵盤事件驗證四類列表。
- 1,000 筆遊戲一次 End 到真正底部，重複 End 不重複載入；到達底部前查詢的封面少於 100 筆，回捲至中段時會再載入可視封面。
- 驗證上下各 80 像素、連續按鍵、Home、空清單、不足一頁、取消定位，以及排序、篩選、分類或媒體切換後不跳回舊清單底部。
- 驗證搜尋、備註、下拉、可編輯區、修飾鍵、已處理事件、分類選單和截圖快篩；彈出視窗輸入與按鈕均不捲動背景。
- 最終 `npm run release:check --workspace catchlist-reader` 通過版本防護與全部 166 項測試，`git diff --check` 通過。

驗收使用隔離資料與模擬網路，不寫正式報告或個人紀錄。沒有宣稱已對真實完整收藏清單人工逐筆驗收。
