## 可用訊號與缺失規則

| 欄位 | 可確認的正向訊號 | 缺失或異常時 |
| --- | --- | --- |
| 中文名稱 | `#appHubAppName` | 缺少標題即不完整頁面；英文標題原樣保留。 |
| 發行日 | `.release_date .date` | 無法解析時為 `unknown`。 |
| 社群標籤 | `.app_tag` | 空標籤不能推論為沒有排除類型，為 `unknown`。 |
| 支援繁中 | `#languageTable .game_language_options` 的「繁體中文」列 | 沒有語言表為 `unknown`。 |
| 免費 | 免費遊玩路徑加上 `data-price-final="0"` | 只看到零價或沒有購買區塊都為 `unknown`。 |
| 內購 | 「遊戲內購買」內容分級文字 | 找不到文字為 `unknown`，不視為否。 |
| MMO | `category2=20` 或「大型多人線上」功能列 | 找不到訊號為 `unknown`。 |
| VR | `vrsupport=401` 是僅限 VR；`vrsupport=402` 是可選 VR | 找不到訊號為 `unknown`。 |
| 搶先體驗 | `#earlyAccessHeader` | 找不到訊號為 `unknown`。 |

HTTP 非 200、年齡驗證，或 HTTP 200 但缺少 `#appHubAppName`，都必須標為待重試，所有硬性欄位維持 `unknown`。這涵蓋地區限制、下架與版面不完整，不可因為回應成功就當成安全資料。

## 全球終身評價：阻擋缺口

繁中頁的 `#userReviews` 同時出現最近 30 天的全語系評價，以及繁體中文的終身評價；它沒有「全部評論」的全球終身好評率與評論數列。

以 AppID 620 為例，頁面顯示繁體中文終身 1,749 則；官方 Reviews API 的 `language=all` 對照值是 466,412 則。兩者顯然不能互換。

A1 固定樣本的 `review-api-all.json` 保存 AppID 620 與 546560 的官方 all-language 對照值，但只作驗證證據。A1 契約檢查器與日後初始化正式流程都沒有呼叫 Reviews API、搜尋頁或 `appdetails`。

因此商店單頁可安全取得許多正向排除訊號，卻無法在既定口徑下穩定取得全球全部語言、終身累積的評論數與好評率。
