# Steam 遊戲資料重抓專案規格

## 目的

以目前已驗證的 Steam 資料抓取途徑，重新建立 2015 年 1 月至 2026 年 3 月的本機遊戲資料。完整資料先留在 `steam_discovery/preview/`，供人工審視；本專案不改動檢視器，也不寫入或覆蓋雲端 `遊戲.md`。

## 需求

- **REQ-001 資料範圍**：重抓 2015-01 至 2026-03，僅處理已上市滿 6 個月的月份。
- **REQ-002 執行單位**：一年使用一個 Codex task；同一個年度 task 內逐月、單線依序抓取。完成並驗證整年後，才建立下一年度 task。
- **REQ-003 本機輸出**：正式重抓結果只寫入 `steam_discovery/preview/遊戲.md`、`遊戲標籤.json` 與輔助連結檔，不碰雲端正式資料。
- **REQ-004 選取門檻**：搜尋全語系；好評率至少 85%、評論數大於 500；排除免費遊玩、內購、搶先體驗、MMO、純 PvP、排除清單中的競技標籤、軟體及僅限 VR 的項目；18+ 內容不排除。
- **REQ-005 新增欄位**：每筆資料須包含 Steam AppID，以及繁體中文、簡體中文的支援狀態；任一為是，即可判定支援中文。
- **REQ-006 社群標籤**：成功抓取時寫入 1 至 20 個社群標籤及 `fetchedAt`；抓取失敗時允許該 AppID 標籤為空，並保留可供後續補抓的紀錄。
- **REQ-007 固定模型**：所有逐月抓取與固定驗證使用 `gpt-5.6-luna`、`low` 思考程度。若該模型不可用，停止並請使用者決定，不得自行替換模型。
- **REQ-008 年度交接**：年度閘門為 PASS 後，自動用同一個本機專案建立下一年度 task；未通過不得前進。
- **REQ-009 失敗處理**：單月失敗時留在當年度 task 重試、查明原因或 correct-course，不得跳月或建立下一年度 task。
- **REQ-010 年度驗證**：確認月份完整、Markdown 可解析、AppID 唯一、門檻與付費條件正確、中文欄位合法、標籤齊全、既有檢視器可讀，且雲端檔案雜湊未變。

## 品質與安全要求

- 每個年度開始前執行 Steam 套件測試；每月命令必須以 exit code 0 結束。
- 使用現有檢視器解析器驗證本機輸出，但不得修改檢視器程式碼或畫面。
- 保留現有原子寫入行為，避免中途中斷造成半份資料。
- 年度 task 不得修改門檻、格式或抓取程式；發現程式問題時標記 CONCERNS 或 FAIL，並進入 correct-course。

## 非目標

- 不修改 `catchlist_reader` 的畫面、欄位或互動。
- 不複製、覆蓋或刪除雲端正式資料。
- 不在年度 task 內開子代理或並行抓不同月份／年份。
- 不重新設計 Steam 抓取器；程式修正須另行記錄與驗證後才能恢復資料重抓。

## 完成標準

- Y2026 至 Y2015 共 12 個年度階段全部 PASS。
- 2015-01 至 2026-03 每個目標月份恰好出現一次，且資料符合 REQ-004～REQ-006；標籤抓取失敗的個案可留空但須記錄。
- 本機完整資料可由既有檢視器讀取，雲端基準雜湊全程不變。
- 最終人工審視與是否搬移至雲端維持待辦；這兩項不阻擋年度自動接續，實際覆蓋仍須另行明確授權。
