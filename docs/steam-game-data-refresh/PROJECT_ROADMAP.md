## 所有年度共用的執行契約

1. 讀取 `STAGE_STATE.yaml`，確認目前年度、前一年度狀態、固定模型與雲端基準雜湊。
2. 執行 `npm test --workspace steam_discovery`。若失敗，停止資料抓取並 correct-course。
3. 記錄 Git branch、HEAD 與工作目錄狀態；保留既有未提交變更，不得清理或覆寫。
4. 同一個 task 依該年度的月份清單逐月執行；上一個月 exit code 0 且輸出已驗證後，才執行下一個月。命令格式：

   `npm run update --workspace steam_discovery -- --year YYYY --month MM --output "D:/練習/CatchList/steam_discovery/preview/遊戲.md"`

5. 年度月份全部完成後執行：

   `npm run update --workspace steam_discovery -- --backfill-tags --output "D:/練習/CatchList/steam_discovery/preview/遊戲.md"`

6. 執行年度及累積驗證：月份恰好一次、Markdown 可解析、AppID 唯一、所有項目符合選取門檻、中文欄位可辨識、成功抓取者有 1～20 個標籤與 `fetchedAt`；抓取失敗者允許標籤為空但須記錄、既有檢視器可讀、雲端 SHA-256 等於基準值。
7. 單月失敗可在同一年度 task 內重試；相同阻礙連續發生三次、需要修改程式，或無法確認資料正確時，閘門不得 PASS，須 correct-course。
8. T4 為 PASS 才更新所有狀態文件，並依 `handoff-new-task` 用同一個本機專案建立下一年度 task，明確指定 Terra＋中等。呼叫 `mcp__codex_app__create_thread` 時，`projectId` 必須放在 `target.projectId`，不可放在最外層；`target` 固定為 `{ type: "project", projectId: "b6066e75-7984-4d3b-91da-170208ca6144", environment: { type: "local" } }`。建立後必須確認回傳 task ID，才可宣稱下一階段開始。CONCERNS 或 FAIL 留在本 task，不建立下一年。

## 閘門定義

- **PASS**：該年度與全部已完成年度均符合完成條件，沒有阻擋性驗收事項。
- **CONCERNS**：命令完成但完整性、限流、舊年份定位或驗證證據有疑慮；不得建立下一年度 task，先 correct-course。
- **FAIL**：測試或抓取失敗、資料格式損壞、雲端雜湊改變，或需要未授權的程式／雲端修改；立即停止。
