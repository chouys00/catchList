# 決策記錄

## DEC-001：完整資料只寫本機預覽目錄

- 狀態：已決定
- 決策：年度重抓一律使用 `steam_discovery/preview/遊戲.md`；標籤與連結檔放在同一目錄。
- 理由：使用者要先審視新版資料，再自行搬移或另行授權覆蓋雲端。

## DEC-002：一年一個 task，同一 task 逐月執行

- 狀態：已決定
- 決策：每個年度各自使用一個新 task；年度內每次只執行一個月份，依月份由新到舊串行處理。
- 理由：單月抓取適合 Luna，也可限制單次失敗的影響範圍；年度邊界則提供清楚的上下文與驗證關卡。

## DEC-003：固定使用 Luna＋輕度

- 狀態：使用者指定
- 決策：資料抓取、補標籤及固定驗證使用 `gpt-5.6-luna`，思考程度 `low`。
- 例外：模型不可用時停止請示，不自動替換。

## DEC-004：由新到舊重抓

- 狀態：已決定
- 決策：順序為 2026、2025，逐年回到 2015；年度內也由較新月份往前。
- 理由：先以近期資料驗證完整流程，若發現資料來源變化可及早修正。

## DEC-005：不並行

- 狀態：已決定
- 決策：`max_workers` 固定為 1，不開子代理，不同月份及年份都不重疊執行。
- 理由：降低 Steam 限流、共享輸出檔競寫與狀態錯置風險。

## DEC-006：人工審視不阻擋年度自動接續

- 狀態：已決定
- 決策：每年通過機器驗證即可接續下一年；完成全部年份後再由使用者審視。本機搬移至雲端仍屬高風險操作，必須另行明確授權。

## DEC-007：下一年度 task 的專案識別必須置於 target

- 日期：2026-09-04
- 狀態：accepted
- 背景：Y2026 PASS 後，曾因把 `projectId` 放在 `create_thread` 最外層而收到 `invalid arguments`，未能建立 Y2025 task。
- 考慮方案：沿用最外層欄位、改用其他模型或改用 projectless task。
- 決定：固定將 `projectId` 放在 `target.projectId`，並使用同一個 CatchList saved project 的 `local` 環境；模型與思考程度仍固定為 Luna＋輕度。
- 理由：符合工具參數結構，並保留未提交的本機資料與年度接力所需狀態。
- 影響：所有尚未開始年度建立 task 前，都要先核對 `STAGE_STATE.yaml` 的 `task_creation_contract`；不得以 projectless 或其他模型繞過。
- 取代關係：補充 DEC-002 與 DEC-003，不取代其年度與模型決策。

## DEC-008：後續年度改用 Terra＋中等

- 日期：2026-09-05
- 狀態：accepted
- 背景：使用者確認 Luna 在 Y2024 執行期間的表現不如預期，要求提高後續工作的可靠性。
- 考慮方案：繼續使用 Luna＋輕度，或改用 Terra＋中等。
- 決定：Y2024 尚未完成的工作與 Y2023～Y2015，資料抓取、補標籤及固定驗證改用 `gpt-5.6-terra`，思考程度 `medium`。
- 理由：後續工作包含 Steam 限流判斷、失敗恢復與年度驗證，需要比機械式逐月執行更穩定的判斷能力。
- 影響：`STAGE_STATE.yaml`、Roadmap、規格、交接文件與 `AGENTS.md` 統一改用新設定；Y2026、Y2025 的歷史紀錄維持不變。
- 取代關係：取代 DEC-003 對尚未完成工作的模型設定，也取代 DEC-007 中「模型仍固定為 Luna＋輕度」的部分；其餘年度、專案與本機環境決策不變。

## DEC-009：完整初始化取代逐年重抓計畫

- 日期：2026-09-11
- 狀態：accepted
- 背景：完整初始化流程已建立並驗收 3,111 款遊戲，使用者也已授權以該結果替換雲端 `遊戲.md`，原逐年重抓計畫不再需要接續 Y2022～Y2015。
- 考慮方案：繼續逐年重抓、同時保留兩套執行計畫，或結束逐年重抓並以完整初始化結果為準。
- 決定：本計畫由 `steam-data-initialization` 取代；Y2026～Y2023 的 PASS 紀錄保留，Y2022～Y2015 不再執行，也不再建立下一年度 task。
- 理由：目前採用資料已完成格式相容、檢視器驗證與雲端替換，繼續執行舊計畫只會重複抓取並產生另一套中間資料。
- 影響：舊 `steam_discovery/preview/` 中間成果刪除並停止追蹤；3,111 筆原始抓取資料保留於本機備份。正常每月更新流程及其限流、定位與失敗保護修正繼續使用。
- 取代關係：取代 DEC-001～DEC-008 對未完成年度的後續執行與交接安排，不改寫已完成年度的歷史證據。
