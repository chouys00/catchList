# 真人劇追蹤器決策紀錄

## DEC-001：資料來源組合

- 日期：2026-08-14
- 狀態：accepted
- 背景：沒有單一平台同時具備五區完整候選、可信評分、繁中名稱與穩定公開介面。
- 考慮方案：只用 TMDb；只用 IMDb；TMDb 加 IMDb；爬取豆瓣或 MyDramaList。
- 決定：TMDb 作候選與主要評分來源，IMDb 作評分佐證，Wikidata 只補繁中名稱。第一版不爬取豆瓣或 MyDramaList。
- 理由：TMDb 可按日期、國家與類型探索劇集；IMDb 有每日更新的公開評分資料，但亞洲劇票數不均；Wikidata 適合補多語名稱，卻不適合排行。
- 影響：實作需要 TMDb 權杖及 IMDb TSV 串流處理；IMDb 缺漏不會讓作品失去資格。
- 取代關係：無。

## DEC-002：分區評估，不建立跨區總分

- 日期：2026-08-14
- 狀態：accepted
- 背景：使用者沒有既定真人劇評分平台與分數直覺，各地區投票母體也不同。
- 考慮方案：固定全球分數門檻；IMDb 換算豆瓣；混合總分；分區校準。
- 決定：五區分開校準投票數與 Bayesian 加權分，報告顯示原始 TMDb／IMDb 分數，不顯示虛構綜合分，也不跨區排名。
- 理由：可減少歐美劇高票數與亞洲劇低票數造成的結構性偏差，使用者也能看懂每筆資料來自哪裡。
- 影響：A1 必須先跑 24 個月樣本，正式門檻在校準後定版。
- 取代關係：無。

## DEC-003：觀察期與月份歸屬

- 日期：2026-08-14
- 狀態：accepted
- 背景：真人劇需要累積播出集數與評分，又要與現有每月更新流程相容。
- 考慮方案：首播後立即收錄；完結後收錄；首播六個月後收錄。
- 決定：按整部劇第一次首播的月份歸檔，預設六個月觀察期。長期連載節目仍只按首次首播月份處理。
- 理由：規則穩定、容易冪等回補，也與電影及遊戲的六個月觀察期一致。
- 影響：新劇不會立即出現在報告；第一版不追蹤每一季或每一集。
- 取代關係：無。

## DEC-007：入選數量與防重複規則

- 日期：2026-08-17
- 狀態：accepted
- 背景：真人劇各地區每月作品數與評價母體差異很大；每月更新也必須避免重複寫入已完成月份或同一作品。
- 考慮方案：每月每區固定名額；每月各取前 20%；依歷史門檻收錄且允許零入選。防重複則比較名稱，或使用月份區段加 TMDb ID。
- 決定：各區依近 24 個合格月份的歷史門檻判斷，不設定固定名額，品質不足時允許零入選。寫入前先檢查 `YYYY  M月` 區段，月份內再以 TMDb ID 去重。
- 理由：不會為了填滿清單收錄普通作品；月份區段可避免重跑，TMDb ID 可避免譯名或名稱變動造成重複。
- 影響：A2 必須測試零入選與歷史門檻；A3 必須測試月份跳過、TMDb ID 去重及同名不同作品保留。
- 取代關係：無。

## DEC-008：零票作品與校準快取

- 日期：2026-08-17
- 狀態：部分由 DEC-009 取代
- 背景：第一次實際校準顯示 TMDb 含大量零票作品。若把零票作品納入評分樣本，五區投票第 25 百分位皆為 0，Bayesian 最低票數也變成 0，無法抑制少量投票造成的虛高。逐筆重寫完整 JSON 快取也會隨資料量增加而明顯變慢，程序中斷時可能留下未完成檔案。
- 考慮方案：零票作品照常納入；設定額外固定票數；保留零票作品於覆蓋率但排除於門檻樣本。快取則考慮逐筆寫入，或批次原子替換。
- 決定：零票或無評分作品仍計入候選、詳細資料與覆蓋率，但不納入區域平均、投票百分位及 Bayesian 門檻樣本。票數門檻仍採各區有評分歷史樣本的第 25 百分位，不另設固定名額或跨區門檻。快取每 50 筆或每月刷新，並以同目錄暫存檔原子替換。
- 理由：可保留 TMDb 覆蓋率事實，同時讓校準反映實際評分分布；批次原子寫入可減少重複磁碟 I/O，避免中斷留下半份 JSON。
- 影響：校準摘要同時保留 `acceptedCount` 與 `sampleCount`；後者只包含票數及評分皆大於 0 的作品。A2 仍依校準所得的各區歷史門檻判斷，不設定固定名額。
- 取代關係：票數百分位由 DEC-009 取代；零票樣本與快取策略維持有效。

## DEC-009：提高最低票數至第 75 百分位

- 日期：2026-08-18
- 狀態：accepted
- 背景：A5 首次實際月份驗證以第 25 百分位為最低票數，2026 年 2 月共入選 22 部，其中 10 部屬低信心，且多部只有 1 至 3 張 TMDb 票，無法符合品質清單對評分可靠度的期待。
- 考慮方案：維持第 25 百分位；另設各區固定票數；改採各區第 75 百分位。
- 決定：最低票數改採各區近 24 個合格月份、有評分歷史樣本的第 75 百分位；Bayesian 加權分數仍採第 80 百分位，不設定固定名額或跨區共用門檻。
- 理由：第 75 百分位會依各區實際投票規模調整，能排除低票數造成的虛高，同時保留五區獨立排序與品質不足時零入選的原則。
- 影響：保留 A1 的 v1 校準檔作為歷史證據，另產生 v2 校準摘要與門檻；A5 必須以 v2 門檻重新完成實際月份 dry-run、兩次暫存輸出與冪等驗證。
- 取代關係：取代 DEC-008 的第 25 百分位票數門檻；其餘決定不變。

## DEC-011：MyDramaList 僅作評分規則可行性核對

- 日期：2026-08-18

- 考慮方案：維持 TMDb 票數硬門檻；直接改用未驗證的 MyDramaList 自動資料；先以 TMDb 候選做 MyDramaList 公開頁面小樣本人工二次核對。
- 決定：使用者授權後者。MyDramaList 在本輪只用於日、韓、台劇候選的人工可行性驗證，不新增爬蟲、不使用未確認的非官方 API、不登入帳號，也不變更正式更新器或正式報告。
- 理由：先驗證資料覆蓋、條目對應與評分人數是否足以支撐規則變更，避免直接以未授權或不穩定來源取代既有來源。

- 取代關係：不取代 DEC-001 或 DEC-009；正式來源與 p75 門檻在使用者根據驗證結果另行決定前維持原狀。
