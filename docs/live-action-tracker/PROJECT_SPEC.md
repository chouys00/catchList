# 真人劇追蹤器專案規格

## 背景與目標

CatchList 已能按季或按月整理動畫、電影與遊戲。真人劇沒有可直接沿用的單一評分平台，而且韓劇、日劇、台劇、陸劇與歐美劇的投票母體差異很大。本功能要新增 `live_action_tracker` workspace，每月整理六個月前首播、已有足夠評價的優質真人劇，增量寫入 `G:/我的雲端硬碟/CatchList/真人劇.md`。

系統以 TMDb 為候選與主要評分來源，IMDb 公開資料集只補充評分與投票數，TMDb 繁體中文翻譯不足時再以 Wikidata 補名稱。各地區分開校準與排序，不產生豆瓣估算分，也不把不同地區硬排成同一份總榜。

外部依據：

- [TMDb TV Discover](https://developer.themoviedb.org/reference/discover-tv) 可依首播日期、原始國家、類型、評分與票數查詢。
- [TMDb TV Details](https://developer.themoviedb.org/reference/tv-series-details)、[Translations](https://developer.themoviedb.org/reference/tv-series-translations) 與 [External IDs](https://developer.themoviedb.org/reference/tv-series-external-ids) 提供劇集細節、翻譯及 IMDb／Wikidata 對照 ID。
- [IMDb 非商業資料集](https://developer.imdb.com/non-commercial-datasets/) 每日更新，提供 `title.basics` 與 `title.ratings` 等 TSV 壓縮檔，限個人及非商業用途。

## 非目標

- 不爬取豆瓣、MyDramaList、串流平台頁面或其他沒有穩定公開 API 的網站。
- 不爬取 Netflix、Disney+、friDay 影音等串流平台頁面；所有劇集的串流可用性只可使用 TMDb 提供、由 JustWatch 支援的臺灣資料。
- 不追蹤單集播出進度、下一集日期或使用者觀看狀態。
- 不修改既有 `動畫.md`、`電影.md`、`遊戲.md` 的格式或門檻。
- 不把 IMDb 或 TMDb 分數換算成豆瓣分數。
- 第一版不使用演員、導演、獎項或社群熱度建立個人化推薦。

## 使用者與主要情境

主要使用者每月執行 `npm run update:all`，系統自動找出 `真人劇.md` 缺漏的月份，只補上六個月前尚未處理的月份。使用者也可執行 `npm run update:tv` 單獨更新，或在開發與驗證時指定年月產生預覽，但預覽不得覆寫正式報告。

## 功能需求

- `REQ-001`：新增 npm workspace `live_action_tracker`，提供 `update`、`test` 與校準用指令。
- `REQ-002`：候選來源以 TMDb `discover/tv` 為主，按目標月份的 `first_air_date` 完整翻頁，不能只取熱門前幾頁。
- `REQ-003`：只保留真人演出的劇情節目。排除動畫、紀錄片、真人秀、新聞、談話節目、綜藝、單集電視電影與成人內容；類型資料不完整時採保守排除並留下原因。
- `REQ-004`：分成韓劇、日劇、台劇、陸劇、歐美劇五組。韓、日、台、陸依 TMDb `origin_country` 的 KR、JP、TW、CN 判定；歐美劇採可維護的國家清單，涵蓋歐洲、美洲及慣例歸入同組的澳洲、紐西蘭。跨國合製依第一個符合的亞洲地區優先，否則歸歐美劇，並保留全部原始國家。
- `REQ-005`：以近 24 個已過六個月觀察期的月份作校準樣本。每個地區分別計算 TMDb 投票數分布、區域平均分與 Bayesian 加權分；這種加權會把低票數高分往該區平均拉回，避免少量投票造成虛高。
- `REQ-006`：正式門檻由校準結果產生並寫入版本化設定。預設每區只收錄近 24 個合格月份的歷史樣本中，加權分位於前 20% 的作品，且投票數至少達該區歷史樣本的第 75 百分位。不得改成每月固定取前 20%，也不得為各區設定強制名額；品質不足時，該月或該區可以沒有入選作品。若某區樣本不足，使用保守的明文備援門檻，不能靜默套用其他地區門檻。使用者可透過追加式決策調整品質門檻；目前日劇、台劇採 7.5，韓劇、陸劇、歐美劇採 8.0，票數門檻仍為各區 p75。
- `REQ-007`：IMDb 透過 TMDb 外部 ID 合併。IMDb 分數只顯示與標記「來源一致／意見分歧／資料不足」，不直接改變 TMDb 入選資格，避免缺少 IMDb 票數的亞洲劇受到不利影響。
- `REQ-008`：中文名稱優先序為 TMDb `zh-TW`、TMDb `zh-HK`、Wikidata `zh-tw`／`zh-hant`／`zh-hk`、原始名稱。不得使用一般機器翻譯臆造片名。
- `REQ-009`：每筆輸出至少包含中文名、原名、地區、首播日期、TMDb 分數與票數、IMDb 分數與票數（若有）、信心等級、類型及 TMDb 連結。
- `REQ-010`：信心等級依該地區投票數分位決定；IMDb 有足夠票數且與 TMDb 同方向時可標記來源一致，但 IMDb 缺漏不得降低信心。
- `REQ-011`：`真人劇.md` 按月份分區，月份內固定依韓劇、日劇、台劇、陸劇、歐美劇排列，各區依 Bayesian 加權分排序。空月份也要寫入完成標記。
- `REQ-012`：報告沿用 `@catchlist/core` 的月份鍵、Markdown 區段、文字清理、重試與原子寫檔能力。寫入前先以 `YYYY  M月` 區段判斷該月是否完成，月份內再以 TMDb ID 去重；同月份重跑不得重複資料或破壞既有月份。
- `REQ-013`：預設只處理執行日往前六個月以前的首播月份，初次執行預設回補最近 12 個合格月份。已有報告時從最早紀錄月到目標終點補齊缺漏。
- `REQ-014`：新增 `npm run update:tv`，並在功能驗收後加入 `npm run update:all`。真人劇失敗時，其他三個專案仍須繼續執行，總指令最後回傳非零結束碼。
- `REQ-015`：TMDb API 權杖優先從 `TMDB_API_TOKEN` 環境變數讀取；若未設定，才讀取 `live_action_tracker/.env` 內同名欄位。`.env` 必須是本機一般檔案並受 Git 排除，不得提交、寫進記錄檔、快取、測試資料或同步資料夾。兩個來源都未設定時，要在發出網路請求前清楚失敗。
- `REQ-016`：提供純本機單元測試與少量需要權杖的實際連線測試。一般 `npm test` 不得依賴網路。
- `REQ-017`：提供 `--dry-run` 或同等預覽模式，顯示候選、排除原因與預計寫入內容，但不修改正式報告。
- `REQ-018`：所有五區劇集除原有 TMDb 評分與票數門檻外，必須在執行當下的 TMDb `TW` 串流可用性資料中至少有一個 `flatrate`（訂閱制）供應商。沒有 `TW` 訂閱制資料時排除；若查詢失敗，整個月份明確失敗，不得誤判為沒有上架。此資料不代表首播當時的歷史上架狀態。報告須標示 JustWatch 為串流可用性資料來源。

## 品質需求

- `QUAL-001`：所有外部請求都要設定逾時，遇到 429、5xx 與暫時性網路錯誤採指數退避重試。
- `QUAL-002`：候選、詳細資料與 ID 對照使用 JSON 快取，快取必須可失效與更新，不得永久保存錯誤回應。
- `QUAL-003`：正式寫檔採逐月原子寫入。中途失敗時，已完成月份可保留，未完成月份下次自動續補。
- `QUAL-004`：分類、加權、門檻、去重、名稱優先序、Markdown 解析及排程失敗隔離都要有自動化測試。
- `QUAL-005`：執行記錄不得輸出權杖，也不得把外部文字原樣插入終端控制序列或 Markdown 結構。
- `QUAL-006`：同一 TMDb ID 在同月份只能出現一次；同名不同作品不得因名稱相同被誤合併。

## 相容性與既有功能

新增功能只能增加 workspace、指令與第四個排程項目。現有三個更新器的輸出、門檻、快取與執行順序保持不變。整體排程仍要在單一專案失敗後繼續處理其他專案。

目前工作樹已有安全寫檔、Windows npm 呼叫相關的未提交修改。真人劇實作必須把這些內容視為既有工作，不得覆蓋或還原；整合階段需以當時實際內容為準重新檢查介面。

## 資料、安全與隱私

- TMDb 權杖屬祕密資料，優先從環境變數讀取；本機 `live_action_tracker/.env` 只作受 Git 排除的備援來源，且不會被程式輸出或複製。
- IMDb 資料只用於本專案的個人、非商業用途，並保留來源說明。
- 不收集個人資料，不登入使用者帳號，不對外傳送報告內容。
- 外部標題、類型與摘要在輸出前清理控制字元；第一版不輸出外部摘要，減少 Markdown 注入與內容污染。
- 快取與校準樣本不得提交大量第三方原始資料；只保留可重現的統計摘要與小型測試樣本。

## 成功條件

- `SUCCESS-001`：五個地區都能從至少 24 個月校準樣本產生覆蓋率、票數分布與建議門檻；資料不足時有明確報告與備援門檻。
- `SUCCESS-002`：固定測試資料能正確排除非真人劇、分到五個地區、合併 IMDb、選中文名並算出穩定排序。
- `SUCCESS-003`：連續執行同一月份兩次，第二次不重抓、不重複寫入，報告內容保持一致。
- `SUCCESS-004`：模擬真人劇更新失敗時，`update:all` 仍會執行動畫、電影與遊戲，最後以非零結束碼回報。
- `SUCCESS-005`：以實際 TMDb 權杖完成至少一個月份的預覽及暫存報告驗證，五區標題、名稱與評分欄位可讀，正式報告未被測試覆蓋。
- `SUCCESS-006`：既有測試與三個原有更新指令的離線啟動／參數測試沒有退步。

## 限制與已知未知事項

- TMDb 對各地區的劇集、類型與繁中名稱覆蓋率尚未以本專案樣本驗證，數字門檻必須等 A1 校準後才能定版。
- TMDb 的投票者組成不是台灣觀眾樣本；本功能只能找出資料來源內相對受好評的作品，不能等同個人喜好。
- `origin_country` 對跨國合製可能不符合文化歸類，第一版採可測試的固定優先規則，並保留日後人工覆寫欄位。
- IMDb ID 與評分對亞洲新劇可能缺漏，因此 IMDb 只作佐證。
- TMDb API 可用性、速率限制與授權條款可能變更，實作時需保留清楚錯誤與可調整的請求節奏。
