# 專案規格

## 背景與目標

CatchList 閱讀器刪除作品後會同步重新讀取全部清單與遊戲標籤，使用 Google 雲端硬碟資料時，列表約需 2～3 秒才刷新。本專案要移除不必要的完整快照，讓刪除與復原只更新受影響資料，同時保留現有備份及原子寫入安全性。

## 非目標

- 不改變 Markdown、`遊戲標籤.json` 或備份檔格式。
- 不取消刪除前確認、刪除備份或立即復原功能。
- 不導入資料庫或第三方套件。
- 不寫入正式 `G:` 資料，不提交、推送或部署。
- 第一版不採用寫檔完成前就移除畫面資料的樂觀更新。

## 使用者與主要情境

使用者在動畫、電影、遊戲或真人劇清單確認刪除後，程式完成備份與寫檔，畫面隨即移除該作品；使用者可立即復原，而且搜尋、篩選、排序與遊戲分批顯示狀態維持正確。

## 功能需求

- REQ-001：Electron 刪除與復原 IPC 不得在每次操作後呼叫 `loadAllLibraries()` 或回傳完整 snapshot。
- REQ-002：刪除成功後，renderer 只更新記憶體內受影響的清單、筆數與畫面，不重新載入其他清單及大型遊戲標籤 sidecar。
- REQ-003：復原成功後，renderer 能把原作品加回正確清單，並維持既有排序、篩選與顯示批次規則。
- REQ-004：等待寫檔期間要防止同一刪除操作重複送出；失敗時原作品仍保留並顯示錯誤。
- REQ-005：刪除仍須先建立獨立備份，再以原子方式取代 Markdown；復原後內容須與刪除前完全一致。

## 品質需求

- 自動測試需證明刪除與復原只回傳局部變更，且不含完整 `libraries` snapshot。
- renderer 測試需涵蓋搜尋、篩選、排序、筆數與遊戲 50 筆分批顯示。
- 全部 Reader 測試與 `git diff --check` 必須通過。
- 正式 Google 雲端硬碟的一般操作目標為確認後 200 ms 內刷新；此項為非阻擋人工驗收，不寫正式資料做自動測試。

## 相容性與既有功能

Electron 閱讀器是本次實作範圍。Tauri shell 的既有行為不得因共用程式碼修改而回歸；動畫、電影、遊戲與真人劇都需維持可刪除與復原。現有未提交的真人劇、五角評分、社群標籤及千筆遊戲效能修改必須完整保留。

## 資料、安全與隱私

測試只使用暫存資料夾或 fixture。不得對正式 `G:\我的雲端硬碟\CatchList` 執行刪除、復原或寫入。錯誤時不得讓畫面與檔案狀態無聲分歧。

## 成功條件

REQ-001 至 REQ-005 全部完成；自動測試證明局部回傳、備份、復原及失敗處理正確；完整 Reader 測試和格式檢查通過。

## 限制與已知未知事項

Google 雲端硬碟單次備份或寫檔仍可能受同步程式影響。若移除完整 snapshot 後，寫檔本身仍常超過 200 ms，需另行評估可回復的樂觀更新，不在本階段自行擴大範圍。
