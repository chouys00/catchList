# 專案 Roadmap

計畫版本：1

整體完成條件：所有 REQ-001 至 REQ-008 已實作並通過完整 Reader 測試與 1,000 筆 Electron 驗證；不提交變更。

階段順序：A1 → A2 → A3 → A4。

## A1：結果分批載入與批次開啟保護

### 需求對應

- REQ-001、REQ-002、REQ-003、REQ-006、REQ-008

### 目標

把遊戲清單改為首次 50 筆、向下捲動時追加 50 筆，並移除全部開啟。

### 非目標

不修改封面快取或標籤索引。

### 前置條件與相依階段

無。

### 預期成果

可重設的顯示筆數狀態、清單底部 sentinel、自動追加但不重建既有列，以及安全的批次開啟限制。

### 實作方向

篩選與排序仍處理完整資料；首次渲染前 50 筆，後續批次以 DOM 追加。篩選條件改變時重置至 50。使用 `IntersectionObserver` 觀察 sentinel，並保留不支援時的可操作備援。移除 `open-all-games` 控制；批次開啟目前結果超過限制時顯示可理解提示。

### 可能影響的系統或資料

`catchlist_reader/src/renderer/app.js`、`item-template.js`、`styles.css`、renderer harness 與測試。

### 階段內任務與並行候選

循序執行；核心 renderer state 與測試互相依賴。

### 必要測試

- 1,000 筆 fixture 初始只顯示 50 筆。
- 觸發 sentinel 後依序變為 100、150 筆，既有列節點保持不變。
- 搜尋與標籤篩選後重置為最多 50 筆。
- 無「開啟全部 Steam」，過量批次開啟不呼叫外部開啟 API。
- `npm run reader:test`、`git diff --check`。

### 完成條件

所有 A1 測試通過，既有搜尋輸入穩定性與標籤 AND 不回歸。

### 人工或外部驗收

- 類型：non-blocking
- 項目：使用者稍後以大量資料手動感受捲動。

### 風險與未知事項

瀏覽器不支援 `IntersectionObserver` 的備援互動需保留可使用性。

## A2：封面延遲載入與持久快取

### 需求對應

- REQ-004、REQ-005、REQ-008

### 目標

只為可見批次取得封面，並把成功網址持久保存於 Electron 使用者資料夾。

### 非目標

不改動 Steam 清單產生器、資料夾內的 Markdown 或標籤 sidecar。

### 前置條件與相依階段

- A1 已 accepted。

### 預期成果

有版本的安全快取檔、原子寫入、損壞回復、封面請求逾時，以及依目前顯示列增量取得／更新封面。

### 實作方向

快取檔放於 `app.getPath('userData')`。主程序先查記憶體及磁碟快取，只對未命中 AppID 呼叫 Steam；只寫入已驗證的 static HTTPS 網址。renderer 不因封面回傳而重建完整已載入列表，改為更新對應 placeholder。

### 可能影響的系統或資料

`main.js`、`steam-covers.js`、新增 cache 模組、`app.js`、`item-template.js` 與測試。

### 階段內任務與並行候選

循序執行；主程序快取介面與 renderer placeholder 需共同設計。

### 必要測試

- 快取命中不觸發 fetch。
- 成功結果可跨新快取實例讀取。
- 損壞快取與逾時不阻斷，失敗網址不保存。
- 封面回傳只更新對應列，不替換既有列節點。
- `npm run reader:test`、`git diff --check`。

### 完成條件

首批最多 50 款會請求封面；重啟後命中快取的 AppID 不再呼叫 Steam API。

### 人工或外部驗收

- 類型：non-blocking
- 項目：首次與第二次啟動的封面載入差異。

### 風險與未知事項

使用者資料夾無法寫入時要退回記憶體快取，不能阻斷閱讀。

## A3：標籤索引與視窗調整節流

### 需求對應

- REQ-007、REQ-008

### 目標

避免標籤面板每次輸入重掃全部遊戲，並避免拖曳視窗時連續重建結果。

### 非目標

不改變標籤排序、AND 規則、已選標籤置頂或面板文案。

### 前置條件與相依階段

- A1 已 accepted。

### 預期成果

資料載入後可重用的標籤統計索引，以及經節流的 resize 處理。

### 實作方向

從 games entries 建立排序後的標籤選項快照，搜尋時只過濾快照；選取狀態在 renderer 組合。視窗變動以 `requestAnimationFrame` 合併，僅在手機／桌機標籤顯示上限跨越時更新清單。

### 可能影響的系統或資料

`game-browser.js`、`app.js`、renderer tests。

### 階段內任務與並行候選

循序執行；兩項都讀寫 renderer state。

### 必要測試

- 索引結果與原本標籤計數、排序、搜尋及選取規則一致。
- 多次同畫面寬度 resize 不重建清單；跨 560px 才更新標籤上限。
- `npm run reader:test`、`git diff --check`。

### 完成條件

標籤互動與響應式行為維持一致，沒有新輸入失焦或捲動回跳。

### 人工或外部驗收

- 類型：none
- 項目：無。

### 風險與未知事項

索引需隨新載入資料與刪除後的 snapshot 正確失效。

## A4：千筆資料整合驗證與手動驗收啟動

### 需求對應

- REQ-001、REQ-002、REQ-003、REQ-004、REQ-005、REQ-006、REQ-007、REQ-008

### 目標

以 1,000 筆合成 fixture 驗證端到端操作，並以隔離資料啟動檢視器供使用者驗收。

### 非目標

不寫入正式資料、不提交。

### 前置條件與相依階段

- A1、A2、A3 已 accepted。

### 預期成果

可重複的 1,000 筆 fixture／harness 證據、完整測試結果，以及持續執行的手動驗收程式。

### 實作方向

使用測試暫存資料或 repository fixture；攔截 Steam 封面請求，不對外大量呼叫。量測初始列數、兩次續載、篩選重置、快取命中與 DOM 節點保持。檢查桌機與手機無水平溢位。

### 可能影響的系統或資料

測試、測試輔助程式與可能的 fixture；不得寫正式資料。

### 階段內任務與並行候選

循序執行；整合驗證依賴前三階段。

### 必要測試

- `npm run reader:test`。
- 1,000 筆 Electron harness。
- `git diff --check`。

### 完成條件

所有 blocking 自動驗收通過，檢視器以隔離資料啟動且供使用者手動測試。

### 人工或外部驗收

- 類型：blocking
- 項目：使用者確認無卡頓、可自動續載、第二次開啟不重抓已快取封面。

### 風險與未知事項

自動測試只能驗證 DOM 與請求數，主觀捲動感受需使用者確認。
