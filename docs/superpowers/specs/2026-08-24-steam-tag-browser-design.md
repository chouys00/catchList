# CatchList Steam 完整標籤與遊戲分頁改版設計

## 目標

將遊戲分頁改為跨月份探索介面。移除月份側欄，預設顯示全部月份的遊戲，並以 Steam 繁中社群標籤提供完整的多選篩選。2026 年 2 月的 7 款既有遊戲及每款 17～20 個實測標籤，是畫面與行為的主要驗收資料。

## 範圍

- 保留 `遊戲.md` 作為遊戲清單及月份完成狀態來源。
- 新增 `遊戲標籤.json`，以 Steam AppID 保存社群標籤，不改寫已鎖定的 Markdown 月份。
- Steam 更新器只替最終入選且快取缺漏的遊戲補抓標籤。
- 提供可續跑的既有遊戲標籤初始化；每筆成功後立即原子寫入，不因中斷重抓已完成項目。
- Electron 閱讀器載入標籤 sidecar，合併至 `遊戲.md` 解析結果。
- 遊戲分頁移除月份側欄，加入跨月份排序、日期篩選與完整標籤多選。
- 動畫與電影分頁維持現行行為。

## 非目標

- 不變更遊戲入選門檻、月份沉澱期或既有歷史區段判定。
- 不在閱讀器開啟時即時向 Steam 抓標籤。
- 不自動改寫正式 `G:\我的雲端硬碟\CatchList\遊戲.md`。
- 不在本次工作推送遠端或建立 PR。

## 標籤資料

### Sidecar 格式

`遊戲標籤.json` 與 `遊戲.md` 放在同一資料夾。根物件保留格式版本與資料列：

```json
{
  "version": 1,
  "locale": "tchinese",
  "games": {
    "3205380": {
      "tags": ["類 Rogue 牌組製作", "烹飪", "物理", "值得重玩"],
      "fetchedAt": "2026-08-24T00:00:00.000Z"
    }
  }
}
```

規則：

- AppID 必須是純數字字串。
- 標籤去除 HTML、壓縮空白、去重並保留 Steam 排序。
- 每款最多保存頁面實際提供的前 20 個非空標籤。
- 無法取得標籤時不寫入空快取；下次仍可重試。
- 讀取到不存在、格式錯誤或版本不支援的 sidecar 時，閱讀器退回 `genres`，其他分頁仍可使用。

### 擷取流程

現行流程維持搜尋頁與 `appdetails` 的職責，完成既有篩選後才讀取個別商店頁標籤：

```text
月份候選 → 既有條件篩選 → appdetails 驗證 → 入選清單
                                              ↓
                                   缺漏者逐款補抓標籤
                                              ↓
                             原子更新遊戲標籤.json → 寫入遊戲.md
```

標籤請求沿用共用 HTTP 重試，預設間隔至少 1.5 秒；429 與 5xx 使用指數退避。初始化從 `遊戲.md` 解析全部 AppID，只處理 sidecar 中缺少的項目，所以大量資料可中斷續跑。

## 閱讀器資料合併

- `loadLibrary` 讀取遊戲報告後，再讀取同資料夾的 `遊戲標籤.json`。
- 每筆遊戲新增 `tags`，有 sidecar 時使用完整標籤；沒有時為空陣列。
- `genres` 保留為正式類型與舊資料備援，不混入 `tags`，避免使用者誤以為兩者相同。
- 測試資料使用工作樹內的隔離資料夾，不寫入正式 `G:` 清單。

## 遊戲分頁資訊架構

### 全清單

- 遊戲分頁不渲染 `.rail` 或月份按鈕，內容寬度與動畫、電影一致。
- 預設顯示全部月份，依上市日期由新到舊，再依好評率與評論數排序。
- 每筆遊戲顯示完整上市日期；月份不再是導覽狀態。

### 第一層篩選

固定工具列包含：

- 名稱搜尋。
- 年份選單，預設所有年份。
- 月份選單，預設所有月份。
- 最低好評率選單，預設不限。
- 「標籤」按鈕，顯示已選數量。
- 清除全部篩選。

### 標籤工作區

點擊「標籤」後展開工具列下方的篩選面板：

- 面板含標籤搜尋框。
- 已選標籤固定顯示在最前方。
- 其餘標籤依目前資料中的遊戲出現次數排序，再依繁中名稱排序。
- 每個標籤顯示符合遊戲數量，例如「策略 5」。
- 多選採「全部符合」語意；選擇「牌組製作」與「輕度 Rogue」時，只保留同時具有兩者的遊戲。
- 面板可收合，收合後已選條件仍以工具列摘要呈現。
- 標籤搜尋只縮小標籤選項，不影響遊戲名稱搜尋。

### 遊戲列

桌面版使用「封面／主資訊／評價與日期／標籤／動作」的橫向列：

- 標籤區預設顯示前 6 個代表標籤。
- 目前已選的篩選標籤優先顯示，即使不在原本前 6 個。
- 其餘以「＋N」按鈕展開；展開只影響該遊戲列。
- 標籤按鈕可直接加入或移除篩選。
- 沒有完整標籤的舊遊戲顯示正式類型，並標示「尚未補齊社群標籤」。

手機版將工具列改為單欄，標籤面板使用頁內抽屜；遊戲列顯示前 3 個標籤與「＋N」，不隱藏評價、日期或主要動作。

## 視覺方向

沿用現有深色編輯工具風格，改成更密集的收藏探索工作區：

- 保留墨黑背景、米白文字與萊姆綠重點色。
- 遊戲列以硬分隔線維持掃讀節奏，不改成卡片網格。
- 標籤使用小型方角按鈕；未選狀態低對比，選取狀態使用萊姆綠底色。
- 標籤面板與清單共用欄寬，避免另外建立左側欄。
- 動畫與電影分頁的版面與顏色不變。

## 錯誤處理與相容性

- Sidecar 不存在：照常顯示全部遊戲，使用正式類型，標籤篩選只列已有資料。
- 單筆 AppID 缺資料：只影響該遊戲，不阻止載入其他遊戲。
- Sidecar JSON 損壞：閱讀器顯示非阻斷提示，保留清單使用能力。
- 舊版 `遊戲.md`、刪除與復原流程維持相容；刪除遊戲不自動刪除 sidecar 快取，避免未來重新加入時重抓。
- Electron 與現有 Tauri shell 共享解析規則；正式使用的 Electron 版先完成完整互動，Tauri 靜態殼同步資料形狀及基本畫面。

## 測試與驗收

### 資料層

- 解析 2026 年 2 月 7 款遊戲並合併 7 筆標籤 sidecar。
- 每款標籤數為 17～20，`你有餅嗎？` 包含「類 Rogue 牌組製作」「烹飪」「牌組製作」等實測標籤。
- Sidecar 缺漏、損壞、重複標籤與非法 AppID 均有測試。
- 初始化只抓缺漏項目，失敗可續跑且不覆寫成功項目。

### 介面層

- 遊戲分頁沒有月份側欄，預設呈現跨月份資料。
- 年份、月份、最低好評率、名稱與標籤可組合篩選。
- 多標籤採全部符合，結果數與清單同步更新。
- 標籤面板搜尋、選取、移除、清除與收合均可操作。
- 遊戲列可展開全部標籤，選取中的標籤優先顯示。
- 搜尋 input 的焦點、游標與繁中輸入不回歸。

### 視覺驗證

- 使用 2026 年 2 月完整標籤資料在 Electron 開發版實測。
- 檢查 1440×900、900×700 與 390×844。
- 確認沒有水平溢位、標籤遮擋、按鈕重疊或主要資訊被截斷。

## 安全與交付

- 所有程式、規格與測試改動留在 `codex/steam-community-tags`，依使用者要求不提交。
- 正式 `G:` 報告與標籤 sidecar 不在未確認前寫入。
- 供使用者驗收的應用程式指向工作樹內隔離測試資料。
